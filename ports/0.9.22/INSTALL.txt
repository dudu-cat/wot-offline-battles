World of Tanks 0.9.22.0.1 #1513 LAN/offline package 0.3.48
================================================================

This folder is directly mergeable into the frozen Chinese HD client root.
It supports standard battles only and always uses the matching Python 3 LAN
server, including when there is only one player.

If you received the ZIP form, extract its contents directly into the game
root. The archive itself contains `mods` and `INSTALL.txt`; it does not add an
extra wrapper directory.

Use `lan_battle_server.py` from the same repository checkpoint as this package.
The v5 message schema is round-scoped and stricter than older v5 packages, so
mixing an old client and new server (or the reverse) is unsupported.
This #1513 client identifies its build during the LAN handshake. The first
client pins an empty server room to one build; a legacy 0.8.2 client cannot join
that room because its map and coordinate contracts are different. Use another
server port for a simultaneous 0.8.2 room.

Version 0.3.48 retains the local gun/shot, collision, spotting and foliage
fixes. It installs one live pose before native input startup for camera, gun,
sniper and minimap consumers; hides unspotted/dead private entities from native
aiming and projectile lookup; restores RPM presentation; and renders admitted
hit direction, health, shot-result and battle-event feedback. Critical hits are
calculated on detached state and committed only through revisioned server
events. Their ordered journal waits for staged Vehicles before native
presentation and also prevents snapshot repair rewind. Hidden bot pose and aim
updates use the private authority registry without widening the native AOI.
Bot collision now uses the
measured 0.8.2 spatial broadphase;
planning is staggered near 10 Hz while physics, gun and network publication
remain at 30 Hz. Version 0.3.48 also gives every Bot its own spawn-route join,
keeps visible enemies as approach targets even before a firing lane opens,
uses per-Bot firing evidence for actual shots, restores player/Bot contact
destruction for trees and fragile props, and separates shot/fire/ram feedback
from friendly collision damage. It refreshes #1513's initial zero ArenaDP
player-id cache before battle markers start. It reads #1513 vehicle components
through their native attributes instead of the disabled legacy mapping API, so
tree contact, wall collision, vehicle dimensions, traverse, dispersion,
critical zones and Bot profiles use the installed vehicle data. It also loads
and owns each synthetic descriptor's BSP hit testers before Bot geometry is
read, rejecting an unloaded bbox instead of substituting a default tank body.
It decodes the pinned #1513 seven-field material-hit result, including its
explicit no-hit flag, before applying the copied 0.8.2 destructible contact law.
Do not mix it with an older
0.9.22 wotmod.

Install
-------

1. Close the game.
2. Delete older `org.peng.offline_lan_0922_*.wotmod` files from:

       <game root>\mods\0.9.22.0.1\

   The old loader scans every package, so leaving an incompatible package next
   to the new one can still stop startup.
3. Copy this folder's `mods` directory into the game root.
4. Confirm this file exists:

       <game root>\mods\0.9.22.0.1\org.peng.offline_lan_0922_0.3.48.wotmod

5. This copy-ready package includes:

       <game root>\mods\configs\offline_lan_0922\config.json

   It is preconfigured for the server address shown in that file. You can also
   change the address in the native LAN settings window described below.
   The same config directory contains validated `navgraphs` and `foliage`
   batches for all 41 supported maps; keep both directories intact.

Start the server
----------------

From the repository on the Mac host, run:

    python3 lan_battle_server.py --host 0.0.0.0 --port 28782 --map server_random

Allow inbound TCP port 28782 through the host firewall when another computer
or virtual machine connects.

Start a battle
--------------

1. Leave the server terminal open.
2. Start `WorldOfTanks.exe` without logging into an online account.
3. On a fresh profile, accept the stock EULA once. Its version is stored in
   `mods\configs\offline_lan_0922\account_state.json` for later launches.
4. Select the tank you want to use, then click the hangar's native Battle!
   button to join the LAN waiting room. The current tank and its descriptor
   health are sent to the LAN server; there is no silent MS-1 fallback. If no
   valid tank is selected, the client stays in the hangar and shows a warning.
   This does not use retail matchmaking or the retail training-room service.
5. If the endpoint cannot be reached, the stock settings window opens
   automatically while retrying. Its Description field contains
   `LAN SERVER: host:port`; edit it if the server address changed. Before a
   welcome, this settings surface does not grant room-host authority. You can
   also click Battle! again while connecting to open it explicitly.
6. The first waiting player becomes room host and receives the stock training
   settings window as a map picker. Its Description field shows the endpoint,
   live player list and `CREATE = START BATTLE FOR EVERYONE`; the host may edit
   the endpoint on the first line and save it there.
7. Every later player clicks the same Battle! button and waits in the hangar.
   Only the host can choose a standard (`ctf`) map and use the window's primary
   action. The server broadcasts that one selected map to every waiting client.
   There is no F12 or `0` key workflow.
   Closing the host picker leaves it closed; the host clicks Battle! to reopen
   it.
8. The server starts the selected map and fills both teams to 15 vehicles.
   The shared 15-second prebattle countdown runs after every human vehicle has
   loaded and the authority has published the bot line-up. Bots continue to
   appear during that countdown, matching the 0.8.2 battle flow. Player
   movement and shooting unlock only when it reaches battle. The server sends
   one ordered tick-zero barrier before snapshots; each client projects its
   relative timing from the network receive timestamp on a monotonic clock.
   The battle debug panel then shows the LAN socket RTT rather than
   retail-server ping.

After a team is eliminated, the battle freezes and returns all connected
players to the waiting room after five seconds. The current host receives the
map picker again. If the host leaves while waiting, ownership and the picker
move to the lowest connected player id. New connections are rejected while a
round is active and may join after the room returns to waiting.

Troubleshooting
---------------

- `unsupported compression type`: an older or incorrectly compressed wotmod
  is still present. Keep only the 0.3.48 package; its members use Store method.
- No connection in the server terminal: check `config.json`, the host LAN IP,
  virtual-machine network mode and TCP 28782 firewall access. A failed attempt
  automatically opens the native endpoint editor; Battle! can reopen it.
- A traceback appears: close the client and keep `python.log`; it identifies the
  exact remaining client API boundary. This package does not create separate
  probe or trace files.

Current boundary
----------------

The release uses native map, Avatar, Vehicle, HUD and collision resources.
Player input follows stock #1513 `PlayerAvatar.moveVehicle` and
`WGVehicleFilter.notifyInputKeysDown`; because no retail server supplies the
resulting transform stream, the copied 0.8.2 integrator owns the canonical
pose and feeds the native camera, gun, minimap and HUD consumers. Remote
vehicles restore the mature 0.8.2 split: a Python gameplay identity owns
pose/health/collision while a separate `OfflineEntity` owns the #1513 compound
model. The LAN layer applies authoritative poses to that presentation and does
not call the forbidden client-side `Entity.teleport` operation.
Bots run on one elected client; the Python server owns shared HP, shot events,
frags, human team-killer state, elimination, standard base capture, the
15-minute timeout and round reset. Non-standard modes are not implemented.
The bot stack uses the finalized 0.8.2 planner, local driver, reverse-steering
recovery and server macro coordinator. Its #1513 navigation batch is baked
from the real terrain, static collision and water resources for all 41
supported standard maps; player and bot formation slots use the same safe
spawn anchors and ground heights. Human player spotting applies the shared
50/500-metre bounds, exact #1513 moving/still vehicle camouflage, shot penalty,
allied relay, five-second memory and pair-specific foliage cover to enemy
models, markers and minimap entries. Detailed post-battle statistics are not
produced. The offline garage contains every complete standard-battle vehicle
definition loadable by this client, with its stock configuration, full crew and
default ammunition. Small repair kits, small medkits and hand extinguishers work
through the stock battle equipment controls. Passive optional-device/skill
modifiers, alternate module purchases and persistent garage mutations are not
implemented. The account starts with 100,000,000 credits, 100,000,000
free XP, 1,000,000 gold, 2,000 garage slots and 2,000 barracks berths. Do not
install this mod into a current or online client.
